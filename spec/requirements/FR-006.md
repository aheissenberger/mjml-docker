## Summary

The repository must ship a multi-stage `Dockerfile` that produces a minimal, production-ready
container image. A dependency stage prepares production dependencies and the runtime stage copies
only the production-necessary files, keeping the final image as small as possible. The dependency
stage uses `node:26-trixie-slim`. The runtime stage uses `gcr.io/distroless/nodejs26-debian13:nonroot`.

## Acceptance Criteria

- `Dockerfile` exists at the repository root
- Both `FROM` lines pin the base image by digest, and the Dockerfile pins an exact pnpm version
- **Dependency stage** (`FROM node:26-trixie-slim@sha256:... AS deps-prod`):
  - Copies `package.json`, the lock file, and `pnpm-workspace.yaml`, then runs
    `pnpm install --prod --frozen-lockfile` to install production dependencies only
- **Runtime stage** (`FROM gcr.io/distroless/nodejs26-debian13:nonroot@sha256:...`):
  - Has no shell and no package manager
  - Does not install pnpm or run dependency installation commands at runtime-image build time
  - Copies `package.json`, `pnpm-lock.yaml`, and production `node_modules` from the dependency stage
  - Copies only `src/` from the repository context
  - Keeps application files root-owned, so the runtime user cannot modify them
  - Runs as a non-root user (`nonroot`, UID 65532, supplied by the base image)
  - Sets `NODE_ENV=production`
  - Requires `API_KEY` env var to be provided at container startup (per FR-005);
    containers started without it will exit immediately with a non-zero code
  - Exposes port 3000 (`EXPOSE 3000`)
  - Runs `src/index.ts` with the `node` binary, which is the image entrypoint
- `docker build .` succeeds without errors
- `docker run --rm -e API_KEY=test -p 3000:3000 <image>` starts the server and
  `GET /health` returns `{ "status": "ok" }`
- A `.dockerignore` file exists and excludes at minimum: `.git`, `.env`, `node_modules`,
  `spec/`, `scripts/`, `test/`, `*.md`

## Verification

- Manual: `docker build -t mjml-docker .` succeeds
- Manual: container health-check passes (`curl http://localhost:3000/health`)
- Automated CI step (optional): `docker build` in the pipeline

## Notes

Both base images ship Node 26 on Debian 13. Because this project
runs TypeScript natively via Node's built-in type stripping (no compile step), the runtime
stage must have Node 26 available — there is no separate compiled JS artefact to copy.
Runtime should avoid package manager installation and dependency resolution; production
`node_modules` should be prepared in a dedicated stage and copied into the final image.
Related architectural decisions: ADR-0004, ADR-0006.
